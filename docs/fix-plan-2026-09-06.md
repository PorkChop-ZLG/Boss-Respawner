## 二、修复任务清单

### T1. 彻底修复 P2-6 / #3：`maxAttempts` 防御性校验

**目标：**  
明确 `maxAttempts` 的边界语义，避免 `0` 被映射成旧默认值 `10`，避免负值意外变成无限重试。

**涉及文件：**

- `src/main/java/com/zonlong/bossrespawner/blockentity/BossRespawnerBlockEntity.java`
- `src/main/java/com/zonlong/bossrespawner/data/RespawnEntry.java`

**修改内容：**

1. `BossRespawnerBlockEntity.normalizeMaxAttempts()` 改为：

```java
private static int normalizeMaxAttempts(int value) {
    if (value < 0) {
        return -1;
    }
    if (value == 0) {
        return 20;
    }
    return value;
}
```

- `-1`：表示无限重试；
- `0`：回退到当前默认值 `20`；
- 正数：按用户配置。

2. 检查 `RespawnEntry.SpawnRule.fromJson()` 的 `max_attempts` 解析，确保不会绕过上述钳制。

**验收：**

- 从损坏 NBT 或手工修改 NBT 中读取 `maxAttempts = -10` 时，最终行为为无限重试；
- `maxAttempts = 0` 时使用默认值 `20`；
- 正常正数不受影响。

### T2. 修复 #1：`removeExistingCages()` 遍历时修改集合

**目标：**  
避免 `replace_existing` 模式在遍历 `chunk.getBlockEntities()` 时调用 `destroyBlock` 导致 `ConcurrentModificationException`。

**涉及文件：**

- `src/main/java/com/zonlong/bossrespawner/placement/RespawnCagePlacer.java`

**修改内容：**

将 `removeExistingCages()` 改为两阶段处理：

1. 遍历已加载区块的 BlockEntity，收集需要销毁的 `BlockPos`；
2. 遍历结束后统一调用 `level.destroyBlock(pos, false)`。

需要补充 import：

```java
import java.util.ArrayList;
import java.util.List;
```

**验收：**

- `replace_existing` 能删除所有真实旧重生笼；
- 不会在遍历过程中修改 chunk 内部集合；
- 无 `ConcurrentModificationException`。

### T3. 修复 #2：`duplicate.mode` 白名单校验

**目标：**  
避免非法 `duplicate.mode` 被误判为 `replace_existing`，防止误删旧笼。

**涉及文件：**

- `src/main/java/com/zonlong/bossrespawner/data/RespawnEntry.java`

**修改内容：**

在 `DuplicateRule.fromJson()` 中增加白名单校验：

```java
String mode = getString(obj, "mode", "allow_multiple");
if (!List.of("allow_multiple", "keep_existing", "replace_existing").contains(mode)) {
    UniversalBossRespawner.LOGGER.warn("Invalid duplicate.mode '{}', falling back to allow_multiple", mode);
    mode = "allow_multiple";
}
```

**验收：**

- 非法值不再触发删除旧笼；
- 非法值静默回退到 `allow_multiple`，并在日志中警告；
- `allow_multiple` / `keep_existing` / `replace_existing` 正常。

- 使用本机缓存 classpath 执行手工 `javac` 全量编译，确认无编译错误；
- 如 Gradle 可用，再执行：
  ```bat
  gradlew.bat compileJava
  ```
- 手动测试范围：
  1. `replace_existing` 模式下重复击杀，确认旧笼正常替换且无异常；
  2. `duplicate.mode` 写入非法值，确认回退到 `allow_multiple` 并出现警告；

  4. 开启调试信息，确认日志不再刷屏且 `offset` 可读；
  5. 达到最大尝试次数后，确认客户端灯笼及时恢复未点亮。
